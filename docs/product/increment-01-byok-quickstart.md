# PicLoom P0.5 增量 PRD：BYOK 开箱即用

> 只描述相对 P0 的**变更**。原始诉求："不应该是需要新建任务组，才能开始使用。而是开箱即用，可以直接填写 BYOK，然后用着先。后续可以分组。"

## 1. 目标与不变量

**目标**：首次打开应用，3 步内出第一张图 —— ①在设置页填 BYOK（Base URL + API Key + 模型名）→ ②在任务页写提示词 → ③点"生成"。全程无需创建模板、分辨率档案或任务组。分组与提示词预设降级为"用着再整理"的可选动作。

**不变量（架构与测试共同约束，不得因本增量放宽）**：

| # | 不变量 |
|---|---|
| I1 | 已派发的生图 POST 永不自动重发；任何上游异常/超时/非 2xx 都不得在本地自动重试或换模型重试。 |
| I2 | UNKNOWN 语义不变：只要派发过且结果不可知，任务进 `Unknown`，不自动回退到 `Queued`。 |
| I3 | 快照不可变：任务落库时的提示词与分辨率参数不随预设/挡位后续修改而变化。 |
| I4 | 密钥安全：API Key 永不回显明文（GET 仅掩码）、不落日志、不进 localStorage/前端持久化、不进错误响应。 |
| I5 | 一次任务 = 一次上游调用。参数校验失败必须在**本地、派发前**拦截，不消耗额度。 |

## 2. 用户故事

1. 首次启动的用户：打开就见到"能直接生成"的表单，填好中转站 Key 与模型名，写一句话，点生成，拿到图。
2. 换服务商的用户：把 Base URL 和应用里显示的模型名换成新的中转站与模型（如 `gpt-image-2` 或第三方别名），点"测试连接"确认可用后继续生成。
3. 想复用写法的用户：把当前提示词存成"预设"，下次从下拉里选回，微调后生成。
4. 只用一次的轻量用户：从不创建分组，所有任务都在"未分组"里按时间倒序浏览。
5. 晚期整理的用户：用了一段时间后把"未分组"里的历史任务挑几条移入新建的分组，旧任务不受影响。
6. 想先确认能跑通的用户：在设置页填好中转站 Base URL 与 Key，点"测试连接"确认可用，再生成；产品内没有无凭据的演示模型，未配置 Key 时只能先去配置。
7. 遇到上游报错的用户：看到的是"密钥无效，请检查设置页 API Key"这类可操作提示，而不是一句"失败"。

### 3.1 分辨率挡位对照表

全部为宽 × 高，均为 16 的倍数，单边 ≤ 3840，宽高比 ≤ 3:1，总像素 655,360–8,294,400。

| 比例 | 1K | 2K | 4K |
|---|---|---|---|
| 1:1 | 1024×1024 | 2048×2048 | 2880×2880 |
| 3:2 | 1536×1024 | 2160×1440 | 3456×2304 |
| 2:3 | 1024×1536 | 1440×2160 | 2304×3456 |
| 16:9 | 1280×720 | 2560×1440 | 3840×2160 |
| 9:16 | 720×1280 | 1440×2560 | 2160×3840 |
| 4:3 | 1024×768 | 2048×1536 | 3200×2400 |
| 3:4 | 768×1024 | 1536×2048 | 2400×3200 |
| 21:9 | 1280×544 | 2560×1088 | 3840×1600 |

规整规则（选"自定义"时逐条校验，任一不满足即在提交前拦截并说明原因）：
1. 宽和高都必须是 **16 的整数倍**（如 1000 会被提示"调整为 992 或 1008"）。
2. 单边 **≤ 3840**。
3. 宽高比 **≤ 3:1**（含反向）。
4. 总像素 **655,360 – 8,294,400**。
5. 表值取自 CookSleep 的 `COMMON_SIZE_PRESETS`，为最终下发值，不再二次缩放；其中 1K/2K 的 3:2、2:3、4:3、3:4 与早期草案不同（早期按面积估算，现按 CookSleep 固定表）。
6. 4K 的 1:1 / 3:2 / 4:3 / 3:4 受总像素上限 8,294,400 约束，分别取 2880×2880、3456×2304、3200×2400、2400×3200；16:9、9:16 与 21:9 恰好或接近上限。
7. 新增"自定义比例"：输入形如 `5:4`、`2.39:1`（支持小数）；命中上表 8 个比例时直接用表值，否则在 16 的倍数网格上搜索，要求比例误差 ≤1%、单边 ≤3840、**宽高比 ≤ 3:1（含反向）**、总像素 655,360–8,294,400，取像素最大的解；无解则报"比例不可用"。

## 4. 交互与状态

### 4.1 任务页三种状态

| 状态 | 触发条件 | 页面表现 |
|---|---|---|
| A. 未配置 Key | 无真实凭据 | 顶部黄色提示 + "去配置"按钮；表单可编辑但"生成"按钮禁用（无试跑入口），模型下拉默认 `gpt-image-1`；若绕过前端直接提交，本地拦截返回 `provider_not_configured`，零上游请求、不创建任务。 |
| B. 已配置可生成 | 有真实凭据 | 提示消失；模型默认 `gpt-image-1`；点"生成"立即创建任务并在列表顶部出现"排队中"。 |
| C. 生成中 / 结果 | 任务已创建 | 状态徽标 排队中 → 生成中 → 成功/失败/结果未知；成功后展示图片与"下载""以此提示词新建"；失败/未知展示 §4.2 文案；轮询在终态停止。 |

### 4.2 错误文案分级（均为中文，含建议动作）

| 场景 | 判定 | 文案 | 建议动作 | 任务终态 |
|---|---|---|---|---|
| 密钥无效 | 401 / 403 | 密钥无效或被拒绝：上游未接受当前的 API Key。 | 去设置页重新填写 Key，并点"测试连接"。 | Unknown（已派发，不重发） |
| 模型不存在 | 404 或"model not found" | 模型不存在：当前 Base URL 下没有这个模型名。 | 检查模型名（中转站常要求 `gpt-image-1` 之类的精确写法）或换 Base URL。 | Unknown |
| 尺寸不被接受 | 400 且响应提及 size/尺寸 | 尺寸不被接受：上游不支持该宽高，请换挡位或自定义尺寸。 | 改用预设挡位（如 16:9 2K）后新建任务。 | Unknown |
| 限流 | 429 | 上游限流：请求太频繁或额度排队中。 | 稍等 1–2 分钟后**手动**新建任务，系统不会自动重试。 | Unknown |
| 网络/超时 | 连接失败、DNS、超时 | 网络异常或超时：无法确认上游是否已生成图片。 | 检查 Base URL 与网络；确认结果前不要重复提交，避免重复计费。 | Unknown |
| 余额不足 | 402 或"insufficient" | 余额不足或额度已用尽。 | 到中转站充值后新建任务。 | Unknown |
| 本地校验失败 | 提交前 | 具体字段错误（如"提示词不能为空""宽高需为 16 的倍数"；格式 JPEG 与透明背景互斥时为 `options_invalid`） | 就地修正后提交。 | 不创建任务 |

**排障口径**：上表每一类都能在日志里查证 —— `scripts/logs.ps1 -TaskId <guid>` 过滤出该任务的 `provider.dispatch`（实际发出的参数）、`provider.failure`（`status`/`errorKind`/`errorSnippet`）与 `task.transition`（`from`→`to`、`errorCode`）；API Key 永不入日志。

## 6. 验收标准

| 编号 | 场景 | 期望可观测结果 |
|---|---|---|
| AC-1 | 空数据库首启，不创建任何模板/分辨率/分组，仅填 BYOK + 提示词 + 1K 1:1 后生成 | 任务创建成功并最终 `Succeeded`，可查看图片；任务列表显示"未分组"；全程未出现"请先创建任务组"阻断。 |
| AC-2 | 保存 Key 后调用读取配置的接口 | 响应体不含明文 Key，只有掩码（如 `sk-…a1b2`）与"已配置"标记。 |
| AC-3 | 保存 Key 后重启应用再打开设置页 | 仍显示"已配置"，仍不回显明文；重启后可直接生成，无需重填。 |
| AC-4 | 清除 Key 后回到任务页 | 回到状态 A（提示 + 去配置），"生成"按钮禁用、无试跑入口；真实模型任务不可提交，绕过前端直接提交则返回 `provider_not_configured`，零上游请求、不创建任务。 |
| AC-5 | 上游返回 400 表示尺寸不被接受 | 任务进入 `Unknown` 并显示"尺寸不被接受"文案；上游仅收到 1 次生图 POST（计数断言为 1）；任务不会自动重发。 |
| AC-6 | 上游返回 401 | 任务进入 `Unknown`，文案指向"检查设置页 API Key"，无第二次 POST。 |
| AC-7 | 上游返回 429 | 任务进入 `Unknown`，文案说明"系统不会自动重试"；无自动重试 POST。 |
| AC-8 | 自定义尺寸输入 1000×1000 | 提交前即被拦截，提示"需为 16 的倍数"；不创建任务，不发请求。 |
| AC-9 | 自定义尺寸输入 5000×500（单边超 3840 / 比例超 3:1） | 分别给出对应错误提示；不创建任务。 |
| AC-10 | 遍历 24 个挡位预设（8 比例 × 3 档） | 每个预设展示的宽高与 §3.1 表完全一致，且全部满足 16 倍数、≤3840、比例 ≤3:1、像素区间约束。 |
| AC-11 | 点击"测试连接"（成功与失败各一次） | 分别显示"连接成功"/"密钥无效"/"无法确认"；任务列表条数不变；无生图计费请求。 |
| AC-12 | 提示词输入 8001 字符 | 显示超限提示且"生成"按钮禁用。 |
| AC-13 | 保存当前提示词为预设，再从预设填入 | 预设出现在列表；点"填入"后提示词框内容与原提示词一致。 |
| AC-14 | 改造前已有分组的历史任务 | 仍能按原分组查询到、图片仍可打开；任务快照内容不变。 |
| AC-15 | 打开任一 `Unknown` 任务详情 | 出现"系统不会自动重发"的明确说明。 |
| AC-16 | 自动模式生成一条任务 | 上游请求体**不含 `size` 字段**；任务详情尺寸显示"自动"。 |
| AC-17 | 自定义比例输入 `5:4 @2K` 与 `2.39:1 @2K`；再输入非法比例 `0:0` | 前两者分别得到 `2288×1824`、`3152×1328`；`0:0` 在提交前被拦截并提示比例不可用，不创建任务。 |
| AC-18 | 无参考图，质量/张数/格式/透明/审核全部保持默认，生成一条任务 | 上游请求体**只含** `model`、`prompt`、`size`；`n`、`quality`、`output_format`、`moderation`、`background` 均不出现。 |
| AC-19 | 添加 2 张参考图后生成 | 发起**一次** `POST {base}/v1/images/edits`（multipart）；`image[]` 恰好 2 个 part，文件名分别为 `input-1.*`、`input-2.*`；未向 `v1/images/generations` 发请求。 |
| AC-20 | 张数=4 用真实中转站生成一次；再用张数=1 生成一次（日常冒烟可用 `LiveTests` 的 `count=2` 多图用例代替） | 前者任务成功且产出 4 张图片，列表卡片显示 ×4 且顺序与落库顺序一致；后者请求体中**无 `n` 字段**（以 `provider.dispatch` 的 `count` 字段核对）；若实际返回张数与请求不符，任务上可见"实际张数"并能看出差异。 |
| AC-21 | 格式选 JPEG 且打开透明背景 | 透明背景开关呈**禁用态**；若强行以该组合提交，则在派发前被拦截（`options_invalid`），零上游请求、不创建任务。 |
| AC-22 | 尝试添加第 5 张参考图；再尝试删除一张已被任务使用的参考图 | 第 5 张被拒绝并提示上限 4 张；已被使用的参考图不可删除，接口返回 `reference_in_use` 且缩略图仍在。 |

**验收方式（统一口径）**：凡涉及上游行为的 AC，一律用**真实中转站冒烟 + 日志字段核对**验证，不再使用进程内演示 Provider —— 冒烟由 `tests/PicLoom.LiveTests`（`Category=Live`）三条用例承担（文生图 / 单参考图 edits / `count=2` 多图，一次共 3 次上游调用；无凭证时 Skip 而非失败），逐条核对用 `scripts/logs.ps1 -TaskId <guid>` 看 `provider.dispatch` / `provider.success` / `provider.failure` / `task.transition` 的字段。
